# 阶段路线与 Gate

本文件维护阶段成果与门禁；当前状态在 [CONTEXT](../CONTEXT.md)，工作拆分在 [DEVELOPMENT_BLUEPRINT](DEVELOPMENT_BLUEPRINT.md)。
Phase 2–4 已获维护者本轮源码推进授权。Gate 顺序保持；源码授权不包含日常机器服务安装、虚拟化启用或系统策略部署。当前进度与具名证据只在 Context。

## Phase 1：Windows 官方捕获限制 PoC

目标：两个原生可编译程序，验证自有 Viewer 的 GPU 输出、WDA、DISPLAY_ONLY 回退和普通捕获路径。
G1 是限定环境的 PoC 验收，不是所有目标 Windows 版本的发布认证。

### Gate G1 — PoC 基线

- Release 构建、启动、持续渲染、resize、最大化/DPI/窗口模式无明显资源问题。
- WDA 成功或明确报告系统失败原因；DISPLAY_ONLY 探测及创建回退可运行。
- CaptureTest 能选择窗口、执行普通捕获、保存 PNG，并区分 API 成功和图像观察。
- 无保护基线与保护模式有真实证据；模拟故障与真实驱动结果分别记载。
- 威胁模型、README、已验证/未验证项完整，禁用方案未进入代码。
- 目标 OS / 外部捕获工具未测项继续登记；不将 G1 写成通用安全边界。

目标矩阵的验收属于 P1-01/P1-02；可在维护者接受未覆盖风险后启动受限 Phase 2 探针，不自动解除发布限制。

## Phase 2：Capture Broker + Shared D3D11 Texture

目标：从自有可信测试 producer 到 Viewer 和 Broker 的分离通路，形成受授权的可信消费者切片。
交付：纹理共享/同步探针、资源生命周期、Broker 协议、身份与 lease、可信输出及撤销证据。
范围仍以自有测试源为主；不声称接入或保护第三方应用原始窗口。

### Gate G2 — 授权内容出口

- 启动前：明确任务授权；G1 证据可复现，P2-01 收敛威胁模型、契约与相关 ADR。
- 共享资源仅交付授权消费者；未知身份、PID 复用、过期 lease、句柄继承/转移有拒绝或明确限制。
- Viewer 仍受官方显示限制；可信录制不通过关闭 WDA 或规避截图 API 获得画面。
- 成功、拒绝、超时、撤销、在途帧、consumer/producer 退出和 GPU/device failure 有实际证据。
- 说明已交付像素不能追回，以及旧资源撤销/轮换的真实有效边界。
- 固定 GPU / adapter / 分辨率环境下记录同步、正确性、资源释放和性能；跨 adapter 未测就不支持承诺。
- 阻断风险已解决、降级或由维护者记录有限接受；能稳定回到 Phase 1 验证路径。

G2-A 于 2026-10-10 由维护者限定接受关闭：具名长测完成资源曲线与轮询 CPU；电功耗和高精度 timer 不可用时的回退性能未测并明确排除相关承诺。G2-A 关闭不代表 G2 通过。G2-B 的 Service 权威 envelope、真实 pipe 客户端身份绑定、Broker 对端检查、逐帧原子预算消费和限定端到端负向场景已实现并验证；G2-C 尚未启动。证据见 [ADR 0009](ADR/0009-authorization-envelope.md) 与 [Service 证据](evidence/p3-service/README.md)。

## Phase 3：Rust SecureService

目标：以 Windows 服务管理策略、身份、授权 lease 与 Broker 生命周期；C++ Viewer / D3D11 保持独立。
交付：Rust 服务、具名 IPC 契约、最小权限账户、策略版本、运行诊断、安装/卸载/恢复方案。
具体 Rust 依赖、账户和 IPC API 需在启动工作包时确定，不在规划中假设已选择。

### Gate G3 — 可运维的策略服务

- 启动前：明确任务授权，G2 的 Broker / 协议收敛，最小权限和服务信任边界 ADR 已接受。
- 服务/客户端身份校验、会话边界、未授权请求、篡改策略、资源预算和 IPC 超时可验证。
- 服务或 Broker 退出/重启、授权失效、策略迁移和日志脱敏可解释，默认拒绝未确认授权。
- 安装/升级/卸载、失败回滚、账户/ACL 设置均有独立受控机器证据；不误删用户数据。
- Rust/C++ 边界、协议版本、依赖锁定与许可证可审查；不在服务中混入渲染职责。
- 无管理员/内核攻击防御的扩大承诺；服务进程存在本身不构成安全保证。

## Phase 4：Hyper-V Secure Workspace

目标：独立 Guest Workspace 运行第三方应用，Host 使用受控显示与授权出口；建立比自有窗口更明确的隔离边界。
交付：硬件/Windows SKU/虚拟化能力探针、Guest/Host 通路、Workspace 生命周期与应用兼容矩阵。
WDAC / VBS / HVCI 为独立评估与部署工作包，不能默认开启或相互替代。

### Gate G4 — Workspace 候选交付

- 启动前：明确任务授权；服务/Broker 通路已验收；虚拟化、数据保留和恢复 ADR 已接受。
- Hyper-V 需求通过实际 feature detection；不支持环境可解释，不暗中降低隔离后仍宣称保护。
- Guest/Host 显示、输入、授权、剪贴板、文件、网络、音频和外设边界逐项记录允许/拒绝/未验证。
- VM 创建/启动/停止/崩溃/升级、快照或备份恢复和删除具备数据安全与受控权限证据。
- Chrome、Edge、微信、QQ、飞书、Office 与其他应用按独立条目验收，不以一个应用替整个生态背书。
- 常见 Host 捕获路径与可信录制同环境对照；记录 GPU/驱动、DPI、多显示器、远程会话和 Guest 限制。
- 安全增强策略的部署、拒绝、恢复、性能与业务影响分别验收。
- 继续排除完全控制 Kernel/Hypervisor 的攻击者与物理拍摄；发布需独立授权及支持/更新/安全披露方案。

## Gate 审查格式

记录环境、实现版本、命令、成功/失败证据、未测项、关联风险、接受人和限定范围。
只使用通过 / 未通过 / 未评审；规划、自动构建或 API 返回成功不自动通过 Gate。
