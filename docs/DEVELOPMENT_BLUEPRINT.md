## Phase 2 工作包

执行依赖：P2-01 → P2-02 → P2-03 → P2-04 → P2-05。风险处理可穿插，但接口收敛先于实现。

### P2-01 设计与身份模型

- 明确 producer、Viewer、Broker、consumer 的身份、同用户威胁、会话和机器权限假设。
- 比较共享资源/IPC 方案，核对官方 SDK，先记录未验证限制；不以进程路径/PID 作唯一凭证。
- 固定 grant/lease、资源 generation、撤销语义与错误分类；输出协议设计、ADR 和负向用例。
- 验收：维护者接受设计范围；不得把接受设计写成安全能力已实现。

### P2-02 共享 D3D11 纹理探针

- 从独立自有 producer 输出可识别帧，Viewer 渲染输入纹理，保留 Phase 1 基线回归。
- 在有界资源数量下验证创建、交付、同步、尺寸/格式、adapter 差异、超时与重建。
- 覆盖 producer 退出、尺寸变化、过期 generation、consumer 异常退出；禁止公开广播共享资源。
- 验收：像素/帧 ID 正确、同步不死锁、owner 清晰、释放证据；精确支持条件据实记录。

### P2-03 Broker 最小授权切片

- 一个生产源、一个合法消费者、一个普通拒绝客户端；版本化消息、身份校验、请求预算、deadline 和终态。
- 测试未知客户端、伪造身份/来源、过期 lease、重放、重复请求、PID 复用与句柄意外交付。
- 验收：拒绝不交付新内容，授权路径不修改 Viewer WDA，错误不会假成功。

### P2-04 可信录制与临时授权撤销

- 实现一个真实受控消费者，先限定单一输出格式/目的地；取消、写入失败和清理有明确结果。
- 覆盖批准、到期、主动撤销、在途帧和旧句柄；必要时轮换源资源，验证停止新帧的实际边界。
- 验收：可信输出可独立读取，普通路径仍按原限制验证，已交付内容无法追回的限制可见。

### P2-05 G2 评审

- 固定环境对照普通捕获与可信输出；测资源、延迟/帧正确性，不先填性能承诺。
- 汇总故障、撤销、同步、身份和未覆盖矩阵；Risk / Contract / ADR 在事实变化时更新。
- 验收：Roadmap G2 每项有证据或限定接受；本轮后续阶段源码授权已覆盖，Gate 与实际系统操作验收仍独立。

## 证据包格式

每个真正开始的工作包记录 ID、问题/假设、OS/设备/版本、源码版本、夹具来源、命令与步骤、实际结果、失败/清理、结论和 Gate/Risk。
后续证据可写在 `docs/evidence/<work-package>/README.md`；启动时创建，不提前生成假结果文件。
大图、日志和二进制进入受忽略产物目录，源码中保留可复现生成方法、脱敏汇总和必要摘要。
